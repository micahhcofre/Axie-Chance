# Internacionalización (i18n): Arquitectura y Guía de Uso

Este documento describe la infraestructura de internacionalización (i18n) de *Axie Chance*, su funcionamiento técnico tanto en el navegador como en Node.js, y las instrucciones paso a paso para agregar textos nuevos o soportar idiomas adicionales.

---

## 1. Arquitectura y Principios de Diseño

El sistema de internacionalización está diseñado para funcionar de manera liviana, sin dependencias externas ni frameworks, garantizando compatibilidad total tanto en el cliente web como en el entorno headless de Node.js (tests unitarios y servidor de salas multijugador).

### Archivos involucrados:

- **`src/i18n.js`**: Módulo central y puro. No accede a `document` ni `window` en su tiempo de carga, lo que permite que `game.js` lo importe en Node sin efectos secundarios. Provee las funciones `tr()`, `currentLang()`, `deviceLang()`, `setLang()` y `translateDom()`.
- **`src/i18n-en.js`**: Diccionario declarativo de traducciones para el inglés (`EN_STRINGS = { 'texto en español': 'English text', ... }`), organizado por secciones según el archivo fuente (`// index.html`, `// lobby.js`, `// tutorial.js`, etc.).
- **`src/main.js`**: Al arrancar la aplicación en el navegador, establece `document.documentElement.lang = currentLang()` y ejecuta `translateDom(document.body)` antes de inicializar la interfaz.
- **`scripts/build.mjs`**: En el empaquetado para producción (`dist/axie-chance.html`), los módulos `i18n-en` e `i18n` se concatenan al inicio de la lista `MODULES` antes de `data`.

### Principio Fundamental: El texto en español es la clave

1. Las claves de traducción son los textos literales exactos en español.
2. Si el idioma activo es español (`'es'`) o si una traducción no existe en el diccionario (`EN_STRINGS`), el sistema devuelve el texto original en español como fallback automático.
3. Esto garantiza que la suite de pruebas existente (que compara mensajes y registros en español) continúe pasando sin alteraciones.

## 2. Funcionamiento del Sistema

### 2.1. Detección y Persistencia de Idioma (`currentLang`, `setLang`)

- La preferencia de idioma se almacena en `localStorage` bajo la clave `axie-chance:lang` (`LANG_KEY`).
- Idiomas admitidos: `es` (español) y `en` (inglés).
- **Idioma inicial**: si no hay preferencia guardada (o la guardada no es válida), `currentLang()` usa el idioma del dispositivo (`deviceLang()`): recorre `navigator.languages` (o `navigator.language`) y toma el primero cuya base (`es` de `es-AR`, `en` de `en-US`) sea uno de los admitidos. Si el dispositivo no habla ninguno, cae en **inglés**.
- La preferencia guardada con el botón de idioma siempre le gana al dispositivo.
- **Aclaración para el servidor en Node.js**: Cuando `globalThis.document` no está presente (por ejemplo, el servidor de salas multijugador en Node), `currentLang()` devuelve `'es'` directamente. Esto evita consultar el `localStorage` experimental de Node, el cual emite advertencias innecesarias en consola.

### 2.2. Cambio de Idioma y Recarga

- En la portada (`#lobby`), arriba a la derecha, se encuentra el botón `#lang-btn` que muestra la alternativa disponible (`EN` si está en español, `ES` si está en inglés).
- Al pulsar el botón, se invoca `setLang(nuevoIdioma)` y se recarga la página mediante `location.reload()`.
- **Razón del reload**: Al recargar la página completa, todas las constantes y estructuras declaradas a nivel de módulo (tales como `POWERS` y `SYMBOLS` en `data.js`, `DIFFICULTY_LABELS` en `adventure.js`, o `ADVENTURE_CAMPAIGN` en `adventure-levels.js`) se reevalúan inmediatamente en el idioma seleccionado, sin necesidad de observadores reactivos complejos.

### 2.3. Traducción Dinámica con `tr(text, params)`

Para textos generados dinámicamente en código JavaScript:

```javascript
import { tr } from './i18n.js';

// Texto plano
const label = tr('Robar carta');

// Texto con parámetros reemplazables
const info = tr('Nivel {n}', { n: 3 });

// Texto con HTML
const msg = tr('Tu ataque vale <b>{pts} puntos</b>.', { pts: 16 });
```

Los parámetros dentro de llaves `{param}` son sustituidos por su valor correspondiente en el objeto `params`.

### 2.4. Traducción de DOM Estático con `translateDom(root)`

Para el HTML estático de `index.html` (portada, modales de reglas, enciclopedia de símbolos, HUD):
- `translateDom` recorre recursivamente los nodos del DOM.
- Traduce el contenido de los nodos de texto normalizando espacios en blanco pero preservando los espacios iniciales y finales.
- Traduce los atributos interactivos y de accesibilidad: `title`, `aria-label`, `alt` y `placeholder`.
- Se ejecuta únicamente cuando `currentLang() === 'en'`.
- **Ojo con los párrafos con etiquetas adentro** (`texto <b>negrita</b> más texto`): cada nodo de texto es una clave aparte, así que la traducción va por pedazos y el orden de las etiquetas queda fijo. Algunas claves son una sola palabra (`'y'`, `'En'`, `'.'`) y se aplican a **cualquier** nodo de texto idéntico del HTML estático. Si una frase no se deja traducir por pedazos, conviene reescribir ese párrafo en `index.html` para que tenga menos cortes.

## 3. Cómo agregar un texto nuevo

### Paso 1: Envolver el texto en el archivo de origen

1. Importar `tr`:
   ```javascript
   import { tr } from './i18n.js';
   ```
2. Reemplazar cadenas de texto visible o template literals por llamadas a `tr()`:
   ```javascript
   // Antes:
   const msg = `Nivel ${num}: ${name}`;
   // Después:
   const msg = tr('Nivel {num}: {name}', { num, name });
   ```
3. **Importante**: La clave pasada como primer argumento de `tr()` **debe ser un string literal directo**. No utilices variables como primer argumento (ej. `tr(variable)`): `test/i18n.test.js` lee cada `tr('...')` literal de `src/` y falla si alguno no tiene entrada en `EN_STRINGS`, y con una variable no puede verlo. Las pocas llamadas con variable que hay (`tr(diffLabel)`, `tr(SEAT_NAME[s])`, `tr(POWERS[p].name)`) traducen textos que ya tienen su entrada por otro lado.

### Paso 2: Registrar la traducción en `src/i18n-en.js`

1. Abrir `src/i18n-en.js`.
2. Ubicar o crear el bloque de comentarios correspondiente al archivo (ej. `// tutorial.js`).
3. Añadir la entrada con la clave exacta en español y su traducción al inglés:
   ```javascript
   'Nivel {num}: {name}': 'Level {num}: {name}',
   ```
4. Si el texto incluye etiquetas HTML o placeholders, asegurarse de conservarlos de forma idéntica en la traducción en inglés.

## 4. Cómo agregar un nuevo idioma

Para añadir soporte a un tercer idioma (por ejemplo, portugués `'pt'`):

1. **Habilitar el código de idioma**:
   En `src/i18n.js`, agregar `'pt'` al array `LANGS`:
   ```javascript
   export const LANGS = ['es', 'en', 'pt'];
   ```
2. **Crear el diccionario de strings**:
   Crear `src/i18n-pt.js`:
   ```javascript
   export const PT_STRINGS = {
     'Jugar': 'Jogar',
     // ...
   };
   ```
3. **Vincular en `src/i18n.js`**:
   Importar `PT_STRINGS` y adaptar `tr()` y `translateDom()` para consultar el diccionario correspondiente según `currentLang()`.
4. **Registrar en el script de empaquetado**:
   En `scripts/build.mjs`, incorporar `'i18n-pt'` a la lista `MODULES` antes de `'i18n'`.
5. **Actualizar la interfaz de usuario**:
   Actualizar `#lang-btn` o crear un selector de idiomas en el menú principal (`src/lobby.js` e `index.html`) para permitir alternar entre los idiomas disponibles.

---

## 5. Limitaciones Conocidas

- **Registro de partidas en red multijugador (`mode: 'net'`)**:
  En partidas online, los eventos del registro de combate (`game.log(...)`) son procesados y redactados por la máquina de estados que corre en el servidor Node.js. Como el servidor opera en español (sin contexto de pantalla del cliente), las entradas del log centralizado se transmiten a los clientes en el idioma del servidor.
