# Axie Chance — Contexto y Guía del Proyecto

Juego de cartas *push-your-luck* para navegador, ambientado en el universo de **Axie Infinity Origins**.
Encadenás símbolos mientras te animes: cuanto más larga la racha de símbolos compartidos, más daño inflige el ataque (fórmula cuadrática $L^2$); pero si la carta robada no comparte ningún símbolo con las rachas todavía vivas, la cadena se corta (*bust*) y el ataque de la ronda hace 0.

> Para el reglamento de juego detallado y balance formal, consultar también [rules.md](rules.md).

## Stack y Convenciones

- **Vanilla Web**: Sin frameworks (React, Vue, etc.) y sin paso de build para desarrollo local. HTML5 + CSS3 + JavaScript moderno con módulos ES nativos (`type: "module"`).
- **Cero dependencias de runtime**: `package.json` no tiene `dependencies`, solo `devDependencies` para tooling (`aws-cdk`, `aws-cdk-lib`, `typescript`).
- **Assets y CDN**: Texturas de interfaz provenientes del kit gráfico de Origins. Imágenes y animaciones de Axies provistas por el CDN oficial de Sky Mavis (`axiecdn.axieinfinity.com`).
- **Tipografía (tres letras, tokens en `:root` de `styles.css`)**: el kit del Origins no trae fuentes; su única letra es la talla de los carteles de resultado (VICTORY/DEFEATED/DRAW), y el sitio de Axie Infinity usa Rowdies + Work Sans. `--rite` (Caesar Dressing, el calco de la talla): solo palabras que anuncian y siempre grandes (resultado, `bigWord` ¡K.O.!/¡SE CORTÓ! vía `FX_FONT.rite`, el VS de la sala); nunca números ni menos de ~28px. `--game` (Lilita One): números, botones, títulos, rótulos, solo en 400. `--text` (Work Sans): lectura, en 400 y 600, nada más grueso. `--mono`: códigos y links. No sumar otra familia ni escribir nombres de fuente sueltos: todo por los tokens (el lienzo, por `FX_FONT`). El link de Google Fonts vive en `index.html`, `spot.html`, `trailer.html` y `FONTS` de `scripts/build.mjs`. `motion-reel/` trae sus propias fuentes locales (Lilita + Archivo) porque sus videos ya están exportados.
- **Audio Engine**: Efectos de sonido WAV descargados bajo demanda y reproducidos vía Web Audio API nativo con AudioContext *lazy*.
- **Archivos generados (NO editar a mano)**:
  - `src/axie-avatars.js` (catálogo de partes y composición de capas de avatares: roster, starters y los rivales de la Aventura tal como salen en cada nivel; más `EVOLVED`, la pila de cada uno del roster con las dos versiones de cada parte, ver `scripts/evolved.mjs`).
  - `src/axie-poses.js` (variantes de poses y animaciones precalculadas: las del roster y las de los rivales del capítulo 1; los del roster llevan además el clip `evolve` y su entrada `<id>@evo`, que guarda solo lo que cambia).
  - `src/poses/rivales-NN.js` (las poses de los rivales de cada capítulo desde el 2, que se cargan cuando hacen falta: ver `rival-poses.js`; los escribe `npm run poses`).
  - `src/audio-clips.js` (mediciones y buffers de clips de audio).
  - `src/vfx-clips.js` (metadatos de sprites de efectos visuales).
  - `Icons/result-*.png` (telas, ramas y telarañas de las pantallas de resultado del kit; los escribe `npm run result-art`).
  - `Icons/menu-*.png` (banderines de PvP y medallones de etapa del kit para los duelos; los escribe `npm run menu-art`).
  - `Icons/status-*.png` (los íconos de estado del kit, `Textures/StatusIcons`, que lleva la chapa: sangrado, herida, burbuja, bloqueo de cura, silencio, mareo…; los escribe `npm run status-icons`).
  - `Backgrounds/menu-loop-{wide,tall}.{mp4,jpg}` (el video de la pelea en loop y su póster; los exporta `motion-reel/tools/render.mjs video --comp loop`. La portada ya no lo usa: detrás de todo está el mapa).
  - `Axies/<id>/*.png` (dibujos de los starters de Origins cortados del atlas del kit; los `*-lv2.png` son la parte de su cuerpo despierto, `N-1` en el kit; los escriben `npm run axies` y `npm run poses` vía `scripts/starters.mjs`).
- **Tests**: Corren en Node.js puro usando un DOM shim ultraligero (`test/dom.mjs`), sin frameworks pesados ni dependencias externas (usa `node:assert/strict`).
- **Convención de idiomas**: Código fuente (variables, funciones, clases, identificadores) en **inglés**; UI, comentarios explicativos, textos y documentación en **español**.
- **Infraestructura AWS**: Código de infraestructura como código (IaC) en TypeScript con **AWS CDK v2** bajo la carpeta `infra/`.

## Comandos del Proyecto

```sh
npm start              # Servidor dev con live reload + servidor de salas en red (http://localhost:8000)
npm test               # Ejecuta las suites de test unitarios e integración en Node
npm run build          # Empaqueta el juego en dist/axie-chance.html (archivo único con assets inlined)
npm run balance        # Banco de balance: simula partidas sembradas y mide efectividad de poderes (--worth <poder>=a,b: su peso para la CPU; --adventure: cuánto gana el rival de cada nivel contra el jugador esperado de esa altura; --bare, --rival-hp, --rival-cpu para probar palancas)
npm run perf           # Banco de rendimiento en Chrome headless: carga, mesa en reposo y partida (--throttle 4, --no-gpu, --only)
npm run layout         # Banco de pantallas en Chrome headless: botones del turno y del centro adentro de la ventana en 6 tamaños (--only 844x390)
npm run axies          # Regenera src/axie-avatars.js desde el mixer de Axies (offline)
npm run poses          # Regenera src/axie-poses.js (animaciones y poses horneadas)
npm run vfx            # Procesa y regenera el atlas de efectos visuales (src/vfx-clips.js)
npm run sfx            # Regenera src/audio-clips.js (mediciones y duraciones de SFX)
npm run result-art     # Corta de las pantallas de resultado del kit las piezas Icons/result-*.png
npm run menu-art       # Corta del kit los banderines y medallones del menú de modos (Icons/menu-*.png)
npm run status-icons   # Baja del kit los íconos de los estados de la chapa (Icons/status-*.png)
npm run deploy         # Construye y despliega los dos stacks (zona DNS + sitio y relay) vía CDK
npm run deploy:dns     # Solo la zona de sindados.com.ar: primer paso en una cuenta nueva (delegar en NIC.ar)
npm run cdk:bootstrap  # Prepara la cuenta para CDK (una sola vez por cuenta)
npm run cdk:diff       # Inspecciona diferencias pendientes de infraestructura AWS (perfil `axie-chance`, o el de `AWS_PROFILE`)
npm run cdk:synth      # Sintetiza la plantilla CloudFormation de la infraestructura
```

## Arquitectura del Sistema

El proyecto sigue una arquitectura estricta en capas unidireccionales **sin dependencias circulares**:

```
data.js ← rules.js ← ai.js
   ↑          ↑         ↑
   └──────── game.js ───┘  (máquina de estados pura: sin DOM, sin audio, sin red)
                ↑
    ┌───────────┼───────────┬──────────────┬──────────────┐
  ui.js      lobby.js     net.js     adventure.js    tutorial.js
    ↑           ↑           ↑              ↑              ↑
    └───────────┴───── arena / DOM ────────┴──────────────┘
```

- **`game.js`** es el corazón lógico agnóstico: desconoce la existencia del DOM, Web Audio o WebSockets.
- La reactividad se maneja mediante el patrón observador: `game.subscribe(fn)` (o `game.on('change', fn)`), notificando a `ui.js`, `audio-cues.js`, etc.

## Taxonomía Canónica y Axie Core

El juego implementa formalmente la taxonomía oficial de Axie Infinity:

1. **Orden Cíclico Canónico**:
   $$\text{Planta (0)} \to \text{Bestia (1)} \to \text{Pez (2)} \to \text{Pájaro (3)} \to \text{Bicho (4)} \to \text{Reptil (5)}$$
2. **Partes Anatómicas y Saltos Fijos**:
   - `tail` (Cola): Salto 0 $\to$ Mono-símbolo puro ($[C_i]$).
   - `mouth` (Boca): Salto +1 $\to$ $[C_i, C_{(i+1)\%6}]$.
   - `eyes` (Ojos): Salto +2 $\to$ $[C_i, C_{(i+2)\%6}]$.
   - `ears` (Orejas): Salto +3 $\to$ $[C_i, C_{(i+3)\%6}]$.
   - `horn` (Cuerno): Salto +4 $\to$ $[C_i, C_{(i+4)\%6}]$.
   - `back` (Espalda): Salto +5 $\to$ $[C_i, C_{(i+5)\%6}]$.
3. **Tríadas Canónicas (Piedra, Papel o Tijera)**:
   - **Roca**: Planta y Reptil.
   - **Papel**: Bestia y Bicho.
   - **Tijera**: Pájaro y Pez.
   - *Regla*: Papel vence a Roca; Tijera vence a Papel; Roca vence a Tijera.
4. **Fórmula de Supresión de Counters (Cartas Desfavorables)**:
   Para cada clase base, sus 2 cartas ajenas en el mazo inicial (8 cartas en total) se derivan matemáticamente, una por cada tríada rival:
   - $P_1, P_2$: Presas (las dos clases de la tríada a la que vence).
   - $C_1, C_2$: Counters (las dos clases de la tríada que la vence).
   - **Carta 1**: $[P_1, P_2]$ (Doble Presa).
   - **Carta 2**: $[C_1, C_2]$ (Confinamiento de amenaza counter).
   - El Aliado $A$ (la otra clase de su tríada) no entra: ya está en una favorable.
   *Propiedad demostrada*: las dos cartas no comparten ningún símbolo, así que cada clase ajena aparece a lo sumo una vez entre las desfavorables. No hay cadena asegurada: aunque un mismo símbolo ajeno esté en las seis favorables (Part Evolution), siempre queda una desfavorable que no lo lleva y corta. **No volver a un formato donde un símbolo esté en todas las desfavorables.**
5. **Axie Core — Part Evolution**:
   Las cartas favorables evolucionadas (`isEvolved: true`) incorporan el símbolo de la clase de la parte, expandiéndose a 3 símbolos (o 2 en la cola).

## Mecánicas del Juego y Reglas Fundamentales

1. **Objetivo y Vida**: Cada jugador comienza con **150 HP** (`TARGET`; el tutorial, con 100 en `TUTORIAL_TARGET`, porque su guión está contado para esa vida; un jefe de la Aventura, con la suya en `state.maxHp`: leerla siempre con `maxHpOf(state, player)`). La vida se deriva:
   $$\text{HP} = \max(150 - \text{daño total recibido} + \text{curación total}, 0)$$
2. **El Turno**:
   - Robás la primera carta de tu mazo (o carta atrapada por Burbuja).
   - Cada símbolo de la primera carta abre una racha (*run*).
   - Cada robo sucesivo: si contiene un símbolo vivo, alarga esa racha. Las rachas que no coincidan quedan congeladas. Si una carta no coincide con **ninguna** racha viva, se produce **corte de cadena (bust)** y el ataque vale 0.
   - **Plantarse**: Ejecuta el ataque. El daño base es el puntaje de la cadena ($\sum \text{largo}^2$).
3. **Fórmula de Daño (`swingOf`)**:
   $$\text{Ataque} = \text{Puntaje Cadena (sin las N mejores rachas si hay caracol)} + 10 \times \text{plumas} + 2 \times \text{Rage}\ (+10 \text{ en Furia})$$
   - Si la cadena se cortó, el daño total es 0. Si está entera pero el caracol la dejó en 0, las plumas y la Rage suman igual.
   - Al recibirlo, primero absorbe el **escudo** (`status.egg`, tope 20) y después la **almohada** (`status.pillow`, turnos del rival) le resta `pillowCut` (10) a lo que llega a la vida.
4. **Mercado Central (Draft)**:
   - Hay **6 cartas visibles** sacadas del pool común.
   - Si te plantaste: podés llevarte **1 carta con poder** O **2 cartas sin poder**.
   - Si se cortó la cadena: podés llevarte **1 carta sin poder**.
   - **Elegibilidad**: Podés llevarte cualquier carta que te toque, lleve o no tu símbolo (solo el tutorial limita el centro a tu color). Con alguien en 0 HP no hay draft.
   - **Renovación**: Si ninguna de las cartas que podés llevarte tiene tu símbolo, se puede renovar el centro entero una vez por draft (`renewMarket()`).
5. **Reloj de Turno (`CLOCK`)**, solo en red (`mode: 'net'`; contra la CPU, la Aventura y el tutorial no hay reloj, ver `armClock`):
   - 30 segundos para decidir robar o plantarse (si se agota, te plantás solo y el ataque sale con lo que llegaste a robar).
   - 20 segundos por pick de draft (si se agota, el reparto se cierra con lo que ya agarraste). Al renovar el centro se reinicia a 20 segundos.
6. **Última Chance** (`lastChance()`):
   - Quien queda en 0 HP (cualquiera de los dos) tiene **un golpe más**. El que cierra lo juega en el mismo intercambio; el que abre (o quien cae después de atacar), abriendo la ronda siguiente, solo.
   - Juega su turno con halo de fuego: si logra dejar al rival en 0 HP también, la partida termina en **Empate** (*Draw*).
   - **Overkill**: si el daño pasado el cero supera 30 (`TUNING.overkill`, ver `overkillOf()`), no hay última chance.
   - **Sin cura** mientras está en 0 HP (`heal()` devuelve 0; las hojas no se gastan).
7. **¿Una más?** (`oneMoreOf()`): no es una regla nueva, es la apuesta del **K.O. directo por overkill** anunciada.
   - Al robar, si el ataque armado no es K.O. directo pero una carta del mazo lo haría y otra corta, antes de la carta se anuncia **¿UNA MÁS?** como en el tráiler (`ONE_MORE_MS` = 1,5 s: mesa apagada con `data-mood="hush"`, música abajo con `audio.duck`, `audio.riser`, `bigWord(..., 'ask')`; el reloj se frena). `state.oneMore = { id, player, stage }` con `stage` `'ask'` → `'bust'`, o `'draw'` → `'ko'` | `'short'`.
   - La carta sale en cámara lenta (`flyEpic` en `table-fx.js`): de espaldas al medio de la pantalla, tiembla, se da vuelta en `ONE_MORE_FLIP` y cae en `ONE_MORE_LAND`; el motor espera que caiga. Hasta la vuelta `ui.js` tapa el corte (`veiled`: daño, aro, vigas) y el sonido y el cuerpo esperan (`epicDraw`).
   - Engancha y pasa el overkill: ataca solo (sin última chance, por la regla de siempre). Corta: cero y el trombón triste (`audio.sadTrombone`) mientras el rival festeja. Engancha sin llegar: sigue el turno.
   - Ni en el tutorial ni con alguien en su última chance. La CPU también.
   - **K.O. o última chance** (`wonByKo` en `game.js`): K.O. es ganar con el derrotado en 0 sin haber jugado su última chance. Solo el K.O. se ve como K.O. en la pelea (lo da vuelta, cartel "¡K.O.!"). Si cayó con última chance y su golpe no alcanzó, no hay remate ni cartel: se desploma solo (postura `ko`) y se canta la victoria.
   - **Remate** (`finisher` en `ui.js`): si la partida termina por K.O. pero sin un ataque que lo haya dado vuelta (lo terminó veneno, cáscara o pluma pasado el overkill), el ganador le pega una vez más —solo animación, sin número— y el derrotado cae panza arriba con su "¡K.O.!". Solo un ataque que cruza cuenta como K.O. ya mostrado (el corte se anota contra el mismo que se cortó).
   - **Cuenta atrás** (`koInOf()`, `KO_COUNTDOWN` = 10): "A N DEL K.O." pegada al número de daño (`.swing-ko`) cuando faltan 10 cartas o menos para el **K.O.**, que es tumbarlo sin última chance (pasado el overkill, `directKo`). Si plantarse ahora lo deja en 0 pero se levanta, arriba dice "QUEDA CON ÚLTIMA CHANCE" (`leavesLastChance()`). Cuenta cartas que sigan la racha más larga (`koProjection`, sin mirar el mazo), se recalcula con cada carta que engancha (la de dos símbolos salta más de uno) y nunca sube: `countDown` en el motor la guarda en `state.koCount`, baja por lo menos uno por carta y no baja de 1 hasta el K.O. de verdad. Roja y latiendo de 3 para abajo. Ojo: `.swing-dmg` pone un `-webkit-text-stroke` que se hereda; lo que va adentro lo corta.
8. **Abandono (`forfeit`)**:
   - La partida deja de correr en el acto: quien abandona pierde y **gana el que se queda**, en la ronda que sea.
   - Esa victoria paga Moonshards y AXP solo desde la ronda 4 (`FORFEIT_PAY_ROUND` en `payout.js`), y nunca como K.O.

## Nivel, evolución y el Taller

Diseño completo en [docs/economy.md](docs/economy.md); reglas en [rules.md](rules.md#el-nivel-del-axie-y-la-evolución) y [el Taller](rules.md#el-taller-crear-cartas).

- Cada Axie del roster tiene **nivel 1–60** con su **AXP**; cada subida da 5 **Moonshards** (la moneda, una bolsa para todos).
- Cada **10 niveles** se abre una evolución (seis), que cuesta 300 · 600 · 900 · 1.200 · 1.500 · 2.000 Moonshards. **Se elige la carta** favorable; evoluciona su parte y la carta suma **el símbolo de la clase de esa parte** (`evolveSymbol`; Mech/Dawn/Dusk = la clase del Axie, por ahora). Las dos desfavorables nunca.
- El id lleva las evoluciones (`'buba~horn'`): la partida, el mazo, el dibujo, la revancha y la sala salen de ahí solos. `newMatch` las recibe en `evolved`/`evolved2` y el loadout en `evolved`.
- **La evolución se hace desde la elección de Axies**: la puerta Evolucionar de la vista previa (`evolve-view.js`), con la rueda de símbolos del mazo mostrando cómo queda cada carta antes de pagarla.
- **Reciclar** desde la mochila: una carta suelta devuelve el 10 % de lo que vale su rareza (1 · 3 · 8 · 25 · 80 · 300 Moonshards), con confirmación.
- **Fusionar** desde la mochila, gratis: tres sueltas iguales (mismos símbolos y mismo poder) hacen una de la rareza siguiente. Quedan sus símbolos (y su poder) y se suma uno al azar; de rara a épica queda uno de los tres, al azar, con un poder de su clase. La mítica no se fusiona. Se ve en grande, en la ficha de la mochila: el altar y la ruleta de lo sorteado (`card-scene.js`), como crear en el Taller.
- **El Taller es la forja** (`crafting.js`, `workshop.js`): 10 Moonshards por carta, a la suerte (80 / 15 / 4 % de 1, 2 y 3 símbolos; 0,85 / 0,14 / 0,01 % de 1, 2 y 3 símbolos con un poder de clase), símbolos de cualquier clase y repetibles, una con poder asegurada cada 50. Va suelta a la mochila.
- **Misiones y pase** (`missions.js`, [docs/missions.md](docs/missions.md)): tres del día y cinco de la semana que pagan AXP o Moonshards y puntos de un pase de 28 días que paga llaves (tiradas del Taller sin Moonshards) y Moonshards. **Dos llaves** (`KEY_KINDS`): la común, lo mismo que crear con Moonshards, y la **de oro** (poco común 15 %, rara 70 %, épica 14 %, legendaria 0,75 %, mítica 0,25 %; legendaria asegurada cada 50), que el pase da una sola vez, en el último escalón, y vale 10 comunes o 100 Moonshards. Se ven y se cobran en el panel de las misiones del mapa (`missions-view.js`) y se usan en el Taller.
- **Se ganan jugando** (`payout.js`, tabla en [rules.md](rules.md#lo-que-se-gana-jugando)): en red, ganar paga 10 Moonshards y 10 de AXP, y por K.O. 20 y 20; en la Aventura, la primera victoria de cada nivel (10, o 20 por K.O.) y la estrella que faltaba (+10); empatar, perder, volver a ganar un nivel, la CPU y el tutorial, nada. La AXP va al Axie con que se jugó. La pantalla del final muestra el resumen y el botín. Falta la **energía**. Con `?testeo` se cargan niveles y Moonshards sin jugar.

## Los Poderes de Clase + Free Game

En cada partida estándar se sortea **un poder activo por clase** (6 en total, de `CLASS_POWERS`), más las 15 cartas de **Free Game**. La Aventura no sortea: estrena primero los 12 **amuletos neutrales** y después los 30 de clase, de a poco hasta el nivel 175, y cada nivel pelea con su combinación fija y única (ver Modo Aventura). Los ★ son los 12 de siempre. Reglas completas en [rules.md](rules.md#los-poderes).

**Reglas generales** (`applyPowers` y `onDraw` en `game.js`, números en `TUNING`):
- **Números fijos**: ningún poder mira el golpe, la racha ni cuántas cartas salieron. La única excepción es la **Energy Drink S** (neutral), que dobla los puntos de la cadena una vez y se rompe.
- **Cada copia suma lo suyo** en la misma mano (dos frascos, 10 de veneno); las cartas montadas cuentan.
- **Momentos** (las categorías, `MOMENTS` y `POWERS[id].moment` en `data.js`): son las tres decisiones del turno, y cada poder cae en una y la lleva como etiqueta —ícono pintado en `index.html` (`#mo-draw`, `#mo-stand`, `#mo-bust`) y su nombre: **Al robar**, **Al atacar**, **Al cortarte**; en inglés *On draw*, *On attack*, *On bust*— solo en la explicación, **nunca adentro de la carta**: el cartel del centro al tocarla, el panel de la Aventura (`momentTag`) y la enciclopedia, que se arma de `POWERS` agrupada por categoría (`symbolsGridHtml` en `ui.js`). El texto de cada poder (`note`, `tip`) **no repite su momento** ni el "aunque te cortes": lo dice la etiqueta, que va siempre al lado (lo vigila `powers.test.js`). Los momentos: *al robar* (`onDraw`, vale aunque corte), *al atacar* (plantado sin cortarse, aunque el golpe haga 0: plantarse es atacar) y *al cortarte* (el shuriken, el martillo y el huevo). Lo que suma números fijos (plumas, Rage, Furia, garras) también cuenta con la cadena en 0 por el caracol: el ataque sale igual. Solo las espinas del que recibe piden un golpe mayor que 0.
- **Topes** (entran dos copias enteras): escudo 20 (`shieldMax`, todas las fuentes en `status.egg`), veneno 15, espinas 28, turnos de brote/capullo 9, plumas 3, garras 5, Rage 5. **El sangrado no tiene tope.**
- **Efectos que te ponen** (`DEBUFFS`): cada Limpiador (`status.cleanser`) cancela una aplicación entera (`resist`); la Red Sage los saca todos (`cleanse`). El bloqueo de cura (`healBlock`/`healShut`) lo cobra `heal()`: la primera cura de un turno gasta uno y cierra la cura el resto de ese turno (`healShut` se borra en `beginTurn`); el escudo no lo frena.
- **Sangrado** (`bleedOnDraw`, al robar): **cuenta cartas**. Cada carta cuesta `bleedDamage` (2) de vida y el sangrado baja 1. Con herida abierta (`wound`, de la Energy Drink), cada carta que paga cura 2 al que abrió la herida; se cierra al terminar ese turno. **Veneno** (`tickPoison`): muerde al final del turno del envenenado y baja 1; con `antidote` (el turno en que robó los guantes) cura en vez de morder.
- **Medusas** (`makeJelly` en `data.js`, `jelly: true`): cartas sin símbolos que la Paralyzing Jellyfish mezcla en el mazo del rival. Cortan (o abren sin rachas), se rompen al salir —ni `finishTurn`, ni el rebarajado de `draw`, ni el Secret Egg las devuelven— y `ownedBy` no las cuenta. La chapa las cuenta en el mazo.

## Modos de Juego

### 1. Solo vs CPU (`mode: 'cpu'`)
- Partida estándar contra bot con dificultad seleccionable (`facil`, `normal`, `duro`).
- Humano siempre abre (p1); bot siempre cierra (p2).
- Pool completo de 86 cartas (35 sin poder + 36 con poder + 15 Free Game).

### 2. Modo Aventura (`mode: 'adventure'`)
- Campaña de **200 niveles en 20 capítulos de 10**, con el jefe en el 10: el Valle, la Costa, el Bosque Nevado, la Guarida, el Coliseo, el Bosque de Otoño, la Jungla, la Laguna, la Isla del Verano, la Meseta, el Cañón Rojo, el Cielo, la Caverna, el Desierto, el Ocaso, el Bosque Nocturno, el Salón de Invierno, los Engranajes, el Mar Violeta y el Amanecer, cada uno con su tierra en el mapa y su escenario de pelea. Arquitectura, balance y receta para agregar niveles en [docs/aventura.md](docs/aventura.md); la tabla de niveles en [rules.md](rules.md#modo-aventura).
- **Poderes nuevos hasta el 175, de a poco** (`UNLOCK_ORDER`, `UNLOCK_LEVELS`): los 12 neutrales primero (tres en el nivel 1, uno cada tres niveles hasta el 28) y después los 30 de clase (del 33 al 175, uno cada 4-5 niveles). **Cada nivel, su combinación fija y única** (`levelPowers`): sin sorteo, el que estrena siempre, hasta seis y uno por clase, rotando los que hace más que no salen; ningún nivel repite la de otro (lo vigila `adventure.test.js`). El panel la muestra. Las épicas del rival llevan un poder de su clase ya abierto (si no hay, cualquiera abierto).
- **Tres tramos, de menos a más**: fácil hasta el 60, medio hasta el 130, difícil hasta el 200. La CPU, fácil en los capítulos 1 y 2, normal hasta el 130 y dura de ahí al final; la vida de los rivales comunes sube por tramos (`RIVAL_HP`, `rivalHpAt`: 150, 130 en el Bosque Nevado, y de 140 a 190), que es lo que hace subir la curva (la escalera le da al rival lo mismo que junta el jugador). El panel muestra la vida cuando no es la de siempre.
- **Rivales propios** (`RIVALS` en `src/axies.js`, armados con el mixer; los de los capítulos 6 a 20 salen de un generador sembrado con partes de otra clase y, por tramo, más partes coleccionables de su clase —místicas, Japón, Navidad, verano, Agamo— y alguna Shiny en lo difícil; los ojos y las orejas de verano y el cuerpo místico peludo no se pueden hornear): el de un nivel que estrena poder es de la clase de ese poder. Lo que traen crece por la **escalera del rival** (`RIVAL_LADDER`): cartas de mochila comunes de su clase desde el 3, que se fusionan en poco comunes (23) y raras (43), y partes evolucionadas desde el 31 (`evolvedAt`), dibujadas con el arte `-lv2` del mixer y con Part Evolution en el mazo. **Tope de 4 cartas de mochila, como el tuyo**, y nunca más de lo que tiene el jugador esperado de esa altura (`EXPECTED` en `scripts/balance.mjs`). El id lleva las evoluciones: `'lobo+2'` (`axie()` lo arma). Los de la Guarida y el Coliseo son híbridos y evolucionan primero sus partes de otras clases (ver `npm run balance -- --adventure`).
- **Jefes** (el 10 de cada capítulo: veinte), un escalón de la escalera arriba de su nivel, casi enteros de partes coleccionables y con cuerpos especiales, de 155 a 270 de vida, y pagan el doble (`BOSS_PAY`): más vida (`hp`, en `state.maxHp.p2`), cuerpo o partes de evento/místicas y **amuletos** (`charms`: esas cartas llevan poderes de la combinación del nivel, siempre los mismos: `charmPowers`, `adventureCharms` y `deckFor(…, { charm })`). Música de jefe desde el principio.
- Se juega con cualquier Axie del roster: los **starters ya no son rivales**.
- **Estrellas**: ganar pasa el nivel; la estrella es solo por **K.O.** (el rival cae sin jugar su última chance, `wonByKo`). Pasado con última chance, queda superado sin estrella (`starredLevels`); la pantalla del final lo dice.
- El **mapa** es un solo mundo dibujado en código (`src/map-world.js` + `src/map-art.js`, en pantalla `src/adventure-map.js`): veinte tierras encadenadas, que se pintan de a una a medida que se acercan a la pantalla y se vacían al alejarse (`zoneContent`, `mountZone` en `lobby.js`; con los rivales de sus niveles, después de traer las poses de su capítulo), pintadas con la paleta y la luz de su fondo de pelea, con un camino que sale de la casa del comienzo y pasa por los 200 niveles, el hito de cada jefe detrás de él (los tótems, el barco pirata, el árbol sagrado, la calabaza gigante, el Coliseo y quince más, hasta la puerta del sol del Amanecer, donde termina el camino), y nubes que se mueven sobre lo que falta (`cloudHtml`: los copos respiran y se corren, y cruzan nubes enteras). Todo se mueve: árboles y matas con el viento, ráfagas de aire, polvo de nieve, niebla y arena, matas secas que ruedan por el desierto, ríos que corren, anillos en las lagunas, olas en la orilla, el barco que se mece, los ojos de los tótems y los fuegos fatuos alrededor de la calabaza. De costado en pantallas apaisadas, de abajo para arriba en un teléfono parado. Los rivales de los niveles abiertos esperan vivos al costado de su nivel, cortando el camino; un toque elige el nivel (tu Axie camina hasta el otro costado, frente a su rival), otro toque lo juega. Entrar a un nivel reparte un muro de cartas y muestra la previa (el cara a cara y una cadena que carga) hasta que la pelea está lista (`src/loading.js`). Arriba **tu perfil** (tu Axie en el aro del kit, tu nivel y la barra de experiencia, ver `src/profile.js`) y las estrellas; abajo el panel del nivel elegido: el número del nivel en grande, el nombre, contra quién y la dificultad en tres marcas, el poder que estrena en un naipe (o, si no estrena, la mochila del rival con la gema de cada carta; tocarlo abre el detalle), la estrella del K.O. y un solo botón de pelear. Ni el rival ni el ícono del nivel se repiten en el panel: ya están en el mapa.
- Persistencia de niveles completados y desbloqueados en `localStorage` (`axie-chance:adventure`) con desbloqueo hacia adelante al incorporar nuevos niveles.

### 3. Modo Tutorial Guiado (`mode: 'tutorial'`)
- Partida de 5 rondas guionadas que se aprende jugando: poco texto, una flecha y un brillo celeste. Lineamientos, decisiones y recorrido en [docs/tutorial.md](docs/tutorial.md).
- Una idea por ronda: **objetivo** (bajarle la vida al rival), **cadena** (más larga, más fuerte; la CPU se corta en cámara lenta), **corte** (la rueda de chances de verde a rojo) y el **centro** (tu color), el **Rocket Stamp** que sale del centro y el Rocket **reviviendo una racha** para el remate.
- Gating por paso (`tutorialAllowed`, `tutorialPlainOnly`, `tutorialAllowedCard`) y ganchos del motor: `tutorialSkipDraft` (centro solo en las rondas 3 y 4) y `tutorialBotStandAt` (cuántas cartas roba la CPU). Termina en "¡TUTORIAL COMPLETADO!" con Ir a modo Aventura / Menú principal.

### 4. Modo Red / Multijugador (`mode: 'net'`)
- Partida online entre dos navegadores/dispositivos vía `?red`, desde cualquier país.
- **Sin servidor prendido**: la partida corre en el navegador de quien crea la sala (`src/rooms.js`); un relay por WebSocket (`relay/core.mjs`) solo lleva mensajes. En `npm start` el relay vive en `scripts/dev.mjs`; publicado, en Lambda + API Gateway + DynamoDB (pago por uso, sin costo fijo). **Decisión del dueño: no sumar recursos con costo fijo.**
- Si el anfitrión cierra la pestaña, la sala se cierra para todos; si se le corta el cable, vuelve con su llave y recupera a las pantallas.
- Salas con código de 4 letras, QR de invitación, sorteo de apertura ($50\%$), espectadores y reconexión por `clientId`.

## Motor de Inteligencia Artificial (CPU)

- **Algoritmo**: *Expectimax* con optimización de perfil de mazo (`deckProfile`) que reduce $96$ cartas a $\sim 41$ combinaciones de símbolos.
- **Dificultades (`STYLE`)**:
  - `facil`: Profundidad 1, margen 1.35 (tímida), no juega el final, la mitad de las veces elige del centro al azar (`sloppyDraft`) y no renueva el centro (`renewsMarket`).
  - `normal`: Profundidad 1, margen 1.0, maximiza los puntos de cada turno. Mirar más cartas no le cambiaría nada: con puntaje puro, si robar una no conviene, robar dos tampoco.
  - `duro`: Profundidad 3, juega por la partida (`attackWorth`, pesos en `DURO`): pega contra escudo, Gecko Mask y la vida que queda; dejarlo sin vida vale un bono; cortarse pierde los poderes de la mesa y medio centro; si el rival lo tumba en el próximo golpe va a todo o nada; en su última chance juega a la probabilidad de empatar.
  - Medición (`npm run balance -- --difficulties`): contra un mismo jugador simulado la CPU gana ~28% en fácil, ~68% en normal y ~76% en duro (200 partidas, con los 30 poderes, mazo de 8 y 150 de vida; antes era ~39 / ~55 / ~63% y no se separó qué cambio explica la suba). Con el rebalanceo de poderes de 2026-10 (600 partidas): ~34 / ~63 / ~70%, igual que justo antes del cambio (~33 / ~63 / ~69%). Un draft que leyera la partida (negarle poderes al rival, pesar poderes por vida) se probó y no movió nada.
- **Valoración de Draft**:
  - Evalúa la **conectividad** de las cartas con el mazo propio.
  - Compara la rama de 2 cartas sin poder contra 1 carta con poder mediante la tabla `POWER_WORTH`:
    - Van de 0.85 (`viper`) a 1.8 (`gloves`) (ver `POWER_WORTH` en `ai.js`). Rehechos en el rebalanceo de 2026-10: 1.3 + 0.05 por cada punto que suma llevarse ese poder en vez de lo que se habría llevado (banco parejo: los dos eligen como la CPU, uno se lo lleva siempre y el otro nunca). El Rocket queda en 1.6; los doce neutrales de la Aventura, estimados (1.15 a 1.6) y sin medir. Contra la tabla anterior, la CPU normal +0.8 ±1.2 y la dura +0.5 ±1.5. Mover un peso solo ±0.3 no sale del ruido. Medir con `npm run balance -- --worth <poder>=…`.
  - Todas las dificultades cuentan los huevos sanos de su mesa (`saves`): con uno, el corte del lookahead vuelve a la misma cadena.
  - **Cada vez que se toca un poder** (regla o números de `TUNING`) se re-mide su peso en el mismo cambio: `npm run balance -- --worth <poder>=<actual>,<otros>` pone a la CPU normal con cada valor contra un jugador que elige con los pesos de hoy, pareado contra el primero; queda el que más gana.

## Reglas Críticas para Desarrolladores y Agentes

1. **No editar archivos generados**: `src/axie-avatars.js`, `src/axie-poses.js`, `src/poses/rivales-*.js`, `src/audio-clips.js`, `src/vfx-clips.js`. Si se alteran avatares o sonidos, usar sus scripts de `npm run`.
2. **`game.js` debe permanecer libre de efectos**: No importar `document`, `window`, AudioContext ni librerías de red en `game.js` ni en `rules.js`.
3. **Perspectiva de Asientos**: El motor habla de asientos `p1` y `p2`, nunca de "humano y máquina". Quién controla cada asiento lo define el modo de juego (`isBotSeat`).
4. **Semillas y Determinismo**: Usar siempre `makeRng(seed)` cuando se requiera reproducibilidad en tests o simulaciones.
5. **Cero dependencias externas en runtime**: Mantener la pureza del stack web sin frameworks.
6. **Build de un solo archivo**: `scripts/build.mjs` concatena los módulos sin envolverlos. Todo módulo nuevo de `src/` va en `MODULES` (en orden de dependencias) y ningún nombre de nivel superior puede repetirse entre archivos: si no, `dist/` sale roto aunque `npm test` pase.
7. **Internacionalización (i18n)**: Todo texto visible nuevo pasa por `tr()` y lleva su entrada en `EN_STRINGS` (`src/i18n-en.js`). El texto en español es la clave de traducción y fallback por defecto.
8. **Rendimiento** (lo vigila `test/perf.test.js`; medir con `npm run perf` antes y después). La mayor parte de una partida es la mesa quieta mientras el jugador piensa, y ahí la página no debería trabajar:
   - **Animaciones en bucle solo de `transform`, `opacity` o filtros que no corren píxeles** (brillo, saturación). Un `box-shadow`, `width`, `outline` o `drop-shadow` que late se repinta en el hilo principal a cada cuadro: el brillo va fijo y lo que late es un `transform`. Lo mismo para las transiciones que se re-disparan solas (la rayita del reloj va en `translate`, no en `width`).
   - **No animar lo que no se ve**: el navegador corre en el hilo principal una animación sin cambio visible (ver `appears` en `axie-motion.js`).
   - **Variables CSS que cambian por cuadro, registradas con `@property … inherits: false`** y pedidas con `inherit` solo donde se leen (`--cam-*`): heredadas recalculan el estilo de todo lo que hay adentro.
   - **Nada de leer layout por cuadro** (`clientWidth`, `getBoundingClientRect`) en bucles de `requestAnimationFrame`: `ResizeObserver`, o medir una vez por cuadro. Y un bucle que puede ir más lento espera con un timer: cada `requestAnimationFrame` despierta la página entera aunque no dibuje.
   - **WebGL solo con placa de video** (`failIfMajorPerformanceCaveat`); si no, el lienzo 2D.
   - **Después de tocar `styles.css`, `npm run layout`**: los tests no ven el CSS, y las superposiciones en pantallas bajas solo se ven midiendo.
   - **Módulos nuevos de `src/` que carga `main.js`**: su `<link rel="modulepreload">` en `index.html` (además de `MODULES` en `build.mjs`).
   - **Recursos pesados que no hacen falta ya** (los atlas de los poderes, varios MB cada uno) van a la fila de `preloadVfx(key, { later: true })`: de a uno, con la página libre, y ninguno con ahorro de datos.
   - **Lo de la Aventura va de a un capítulo**: las poses de los rivales (`rival-poses.js`, ~200 KB por capítulo) y el dibujo del mapa (una tierra a la vez, `zoneContent`). Un capítulo nuevo no agrega peso a la carga inicial; si algo de un capítulo se necesita al abrir el juego, es un error.
